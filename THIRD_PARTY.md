## Artwork and branding

All current project artwork is self-authored and generated by
`tools/generate-project-artwork.py` (see [res/ARTWORK.md](res/ARTWORK.md)):
two offset quadrilateral planes joined by circular control points in a
dark-ink, warm-cream, vermilion, and cyan palette, plus a small bitmap
`SOUL2D` wordmark drawn from glyph data in the generator. This covers
`res/icon.png`, `res/logo*.png`, `res/ui/banner*.png`, `res/ui/grid.png`,
`res/ui/ui-ada.png`, `res/ui/ui-info.png`, `res/ui/ui-warning.png`,
`res/ui/ui-error.png`, `build-aux/osx/soul2d.iconset/`,
`build-aux/osx/dmgbg.png`, `build-aux/windows/soul2d.ico`, and the
WiX bitmaps under `build-aux/windows/wix/res/`. No prior project artwork
is reused in the generated files; they carry the project's BSD-2-Clause
terms.

Inherited artwork that previously occupied these paths was replaced on
2026-10-11 because its source-redistribution terms could not be
established. Historical attribution remains in
[CONTRIBUTORS.md](CONTRIBUTORS.md); those earlier works are not distributed
in this repository or its history. This repository does not claim rights over the
replaced third-party artwork or any trademark rights of upstream projects.

## External dependencies

Rust dependencies are listed in `rust/Cargo.toml` and resolved by
`rust/Cargo.lock`. The core uses base64, crc32fast, flate2, image, roxmltree,
serde, and serde_json; the optional `gui` feature adds eframe (egui, winit,
and OpenGL through glow) and rfd for the native file dialog. On Linux the GUI links against the system
libxkbcommon. The earlier D dependencies (i2d-imgui, psd-d, kra-d, the
nijilive-derived engine, SDL2, FreeType, OpenSSL) are no longer used.
`rust/src/psd.rs` and the binding evaluation in `rust/src/evaluation.rs` are
Rust ports derived from psd-d and the nijilive engine (BSD-2-Clause, Inochi2D
and nijigenerate copyright retained in the root `LICENSE`).

Each dependency keeps its own license. The root BSD license does not replace
those licenses. No binary distribution is currently supported.
The [Rust dependency ledger](doc/licenses/rust-dependencies.tsv) lists every
resolved non-workspace crate (name, version, declared license, repository and the
Linux, macOS or Windows graphs that include it) and ships in every artifact.
Regenerate it with `python3 tools/gen-third-party-crates.py` after `Cargo.lock` changes.
The same command writes [the crates' license texts](doc/licenses/rust-dependencies-licenses.txt):
every license, copying and notice file the crates ship, each distinct text once with the crates
that carry it. Crates that ship no such file are listed at its top with only their declared
license in the ledger. The earlier [macOS-only ledger](doc/licenses/rust-dependencies-macos.tsv) is kept
as the record cited by the license review.

## External models and vendor software

Five `synthetic-depth-*.json` fixtures under
`rust/tests/fixtures/depthdraw/` are independent
local-contract records generated by
`tools/generate-synthetic-depth-fixtures.py` (see the fixture directory
README). The earlier external model/tool reference outputs at those
paths were retired to tombstones on 2026-10-11 pending rights clearance;
the tombstones contain no external data. Two pre-existing `local-*.json`
contract fixtures in the same directory are unchanged. The retired copies
are not part of this repository or its history. The synthetic
fixtures are a bounded replacement corpus, not a vendor-equivalence
claim and not a reproduction of the retired comparison coverage.

Live2D sample models, CMO3/CAN3 files, MOC3 files, PSD artwork, proprietary SDK
binaries, and vendor applications are not included as project-licensed inputs.
Verification tools expect separately acquired files in ignored local directories.

The [Live2D Free Material License Agreement](https://www.live2d.com/eula/live2d-free-material-license-agreement_en.html)
and each model's download-page conditions apply independently. Downloading a
sample for verification does not grant permission to publish its model, artwork,
or rendered outputs in this repository.
Section 4.1.7 also restricts combining output files with competing middleware.
Whether Soul2D verification falls within that restriction needs confirmation
before further use of those samples; keeping them outside Git does not resolve
the use conditions.
