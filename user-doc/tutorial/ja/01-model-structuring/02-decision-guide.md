# 02. 判断ガイド

ツリーを編集していると「どの操作を選べばいいか」で手が止まりがちです。  
迷ったら、次の判断だけ先に決めてから手を動かします。

## 3.0 このチュートリアルで言う「親子」は Part 同士のつながり

ここがいちばん誤解されやすいポイントです。

- 「首は胴の子」「目や口は顔の子」「腕は胴の子」のような言い方は、**見た目（画像）を持つ Part 同士の親子関係**を指します。
- `Node` や `GridDeformer` は補助役で、Part の上下に挟み込むことはありますが、**“胴→首→顔” や “顔→目/口” といった骨格のつながりを置き換えるものではありません。**

たとえば胴に `Body::G (GridDeformer)` を挿入する場合、正しい考え方は次のどちらかです。

- `Body::G` の **子に `Body (Part)` を残し**、首は `Body (Part)` の子にする
- どうしても意図があって `Body::G` を親にしたい場合でも、**「胴の基準は Body Part」だと分かる形**にして、首を “胴 Part の子” として扱える状態にする

以降の手順で「〜の子にする」と書いてある箇所は、**まず Part を基準に親子を作り、必要なら途中に Node / GridDeformer を挟む**、という意味で読んでください。

## 3.0.1 Node を挟むのは「独立で動かすことが多いパーツ」だけ

Node を挟むのは万能ルールではありません。  
主に、胴体に対して **独立で動かすことが多いパーツ**（腕・顔、キャラによっては脚など）で使います。

これらは、親（胴体）の変形の影響をそのまま受けると破綻しやすく、また回転の中心も個別に欲しくなることが多いので、親 Part と子 Part の間に **Node を 1 枚挟む**と扱いやすくなります。

基本形は次の 3 段です。

- 親（`Part`）
- `Node`
  子パーツを選んで Insert → Node で作る（3.1 参照）
- 子（`Part` など）

ポイントは「Node を上位で新規追加する」のではなく、**子パーツに対して親として挿入する**ことです。  
こうすると Node の原点が子パーツに揃い、位置ズレを起こしにくく、変形の影響も調整しやすくなります。

## 3.1 「親を 1 段増やしたい」なら Insert（挿入）を選ぶ

**こんなとき**

- 回転の中心（ピボット）を作りたい
- すでにある Part をまとめたい
- 既存の親子関係の「間に」ノードを差し込みたい

**なぜ Insert なのか**

挿入（Insert）は「選んだ対象の親として差し込む」動作なので、**挿入されたノードの原点を対象パーツの位置に合わせやすい**のが利点です。  
逆に Add は「親の子として新規ノードを足す」動作になりやすく、原点が親側の座標や既定位置に寄ってしまいます。結果として、

- 回転させたら大きくズレる
- 変形やマスクの基準が合わない
- 後から直す手間が増える

というケースが大量に起きます。**階層化が目的なら、基本は Insert を選ぶ**と覚えてください。

**操作できる場所**

- ノードツリーでノードを右クリックし、Insert からノードの種類（`Node`、`Composite`、`DynamicComposite`、`GridDeformer` など）を選ぶ
- または「ノード」パネルで「Insert class」に種類を選び、「Insert」を押す
- 名前を付けたいときは、先に「Suffix」を入力する。新しいノードは、選んだノードの名前に Suffix を足した名前になる（`Body` という Part に Suffix `::Root` なら `Body::Root`）。Suffix が空なら既定の名前になる。名前はあとから Inspector の Name 欄でも変えられる
- Insert は、選んだノードそれぞれに別々の新しいノードを作る。複数の Part を 1 つの新しいノードにまとめたいときは、そのうち 1 つに Insert してから、残りをそのノードの中へ移す（ツリー上でドラッグするか、「ノード」パネルの「Move destination」と「Move」を使う）
- MCP では `node_insert` を使う

## 3.2 「すでに階層はあるが、種類が違う」なら Convert To（変換）を使う

**こんなとき**

- すでに `Node` で階層化されているが、本当は `DynamicComposite` にしたい
- すでに `Node` で階層化されているが、本当は `GridDeformer` にしたい
- まとめ役の種類が違うせいで、差分管理やマスクがやりづらい

**なぜ Convert To なのか**

この状況は、ノードを「挿入」や「追加」しても根本は解決しません。  
欲しいのは “階層の追加” ではなく “ノード種別の置き換え” だからです。そこで **Convert To で種類そのものを変える**のが最短です。ノードツリーでノードを右クリックして「Convert To...」を選ぶか、「ノード」パネルの「Convert to」に種類を選んで「Convert」を押します。`Node` は `MeshGroup`、`DynamicComposite`、`GridDeformer` に変換できます。MCP では `node_convert` を使います。

**補足（GridDeformer にしたいとき）**

- すでにその位置に「まとめ用の `Node`」が入っている  
  → その `Node` を `GridDeformer` に **Convert To（変換）** して、その場で置き換える
- その位置に置き換えたい `Node` が無い / グリッドを 1 枚追加して包みたい  
  → 変形させたい **Part** を選び、その **親として GridDeformer を挿入**する

## 3.3 Convert To で Node → DynamicComposite にしたときの注意

Node を DynamicComposite に変換した直後は、表示や当たり判定のリサイズが追いつかないことがあります。  
その場合は `DynamicComposite` の Inspector にある「Resize automatically」（プロパティ名は `auto_resized`）を **2 回トグル**して、リサイズを確定させてください。

## 3.4 目と口は「同じ考え方」でまとめる

目だけ DynamicComposite にして口はバラバラ、という構成にすると、口の差分やマスク管理だけが別ルールになって破綻しやすくなります。  
**口も目と同じように DynamicComposite でまとめる**と、

- 表情差分の追加・切替が楽
- 影やマスクの親子関係が整理しやすい
- 後から拡張しやすい

というメリットがあります。

## 3.5 腕・脚・口など「連結して動くもの」は付け根→先端の順に並べる

連結パーツは親の動きが子へ伝わるため、付け根が親、先端が子の順にすると自然な追従になります。逆に先端を親にすると、

- 付け根が抜ける / 引きつる
- 回転中心が取りづらい
- 物理や変形の設定がややこしくなる

といった問題が起きやすくなります。腕・脚だけでなく、口の開閉・顎周りなども「基準（付け根）→末端（先端）」の順で揃えるのがおすすめです。

## 3.6 Grid / AutoMesh / 一括操作は「作業を減らすための道具」

- GridDeformer の格子数は、顔や後頭部は **8×8 程度**、胴体は **10×14 程度**を起点に、縦横比で微調整します。格子は、Edit Mesh の Grid Vertex Tool で整えます（点をドラッグし、ダブルクリックで線を追加・削除）。「Grid cuts」は新しく描く格子の軸ごとの線の数なので、8 マスなら 9 を指定します。
- AutoMesh（ツールパネルの「Auto mesh」）が作るのは Part のメッシュだけで、Part には Optimum を使います。GridDeformer の格子は AutoMesh では作れないので、自分で定義します。
- 顔や胴体のような広い面は、Part のメッシュだけでなく、外側に GridDeformer を用意しておくと後から大きく動かしやすくなります。
- Part の形に沿わせたい場所は AutoMesh（Optimum）、まとまり全体を格子で動かしたい場所は GridDeformer と考えると選びやすくなります。
- 同じ操作を何度も繰り返す場面は、複数選択して一括で行うとミスが減ります。
- 一括操作のあとは、意図した Part や GridDeformer だけに設定が入っているか確認します。
