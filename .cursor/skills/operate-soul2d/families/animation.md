# Animation

Status: run live against the headless host (create, set, key_add, key_set with interpolation, sample, seek, key_copy, key_paste, advance error, reset).

ACP template save/delete calls need host approval for the exact store file and entry. A changed file or config path expires approval; listing and applying a template do not write the store.

INP/INX animations: named clips with one lane per parameter axis and keyframes at integer frames. Keyframe edits are undoable document
edits; seek, advance and reset are preview only and add no history. For Motion3 clips see motion3.md; for CAN3 (Live2D) see live2d-animation.md.

## Sequence

1. Explore: `parameters {}` for the parameter UUID; `snapshot` (`model.animations`, `animation`) for existing clips.
2. Read: `snapshot.model.animations.<name>` has `lanes` with `keyframes {frame, value, tension}` and `interpolation`; `animation_sample` reads values without touching the session.
3. Act: `animation_create {name}`, `animation_set {name, length, timestep, ...}`, then keys.
   `animation_key_set {name, parameter, axis, frame, value}` writes an explicit value; `animation_key_add {name, parameter, frame}` records the parameter's *current*
   session value (set it first with `value_set`).
4. Confirm: `animation_sample {name, frame}` returns `{values: {<param uuid>: [x,y]}}` for every parameter. `animation_seek {name, frame}` then `render` shows the pose.
   `animation_reset` returns to the manual parameter values.

## Edit a repeating clip

1. Read the clip name and its keys from `resource://vsoul/snapshot`.
2. Call `animation_set {name, loopEditing: true}` to enable loop editing in one undo step.
   The clip must use the full scene interval. `leadIn` is absent, -1, or 0.
   `leadOut` is absent, -1, or the clip's `length`.
3. Read `model.animations[name].loopEditing` and the original keyframes from the resource.
   The flag is true. The saved keyframes have not gained copies.
4. Edit the original keys with `animation_key_set`. Sample the clip with `animation_sample`.
   Loop editing derives neighboring cycles for parameter lanes and eye blinking.
   Exact saved keyframes use their authored values in this mode.
5. Call `animation_set {name, loopEditing: false}` to disable loop editing.
   False removes the flag. Setting false on an unchanged clip without the flag adds no history.

In the editor's animation settings, select **Loop editing support** and click
**Apply animation settings**. The timeline shows linked keys from the preceding
and following cycles. Selecting a copy selects its saved source key. The key value
and tension fields edit that source key, and all copies show the new value.
The playhead stays in the saved clip range.

Form animation, image time remapping, audio, and their metadata are not duplicated.
Shortening a clip past an existing key remains an error, rather than deleting keys.
This is an INX editing feature, not a native Cubism document or vendor compatibility result.
The dedicated MCP check is `tools/verify-animation-loop-edit.py`.
Native GUI input requires a separate run.

## Gotchas

- In the editor, select or seek a clip, then open **Image sequences and timing** in the timeline. Enter the folder and exact filename prefix to add a sequence. The same panel reloads or deletes tracks, sets placement and Guide, edits timing keys, and keys frame steps for the whole clip or a parameter group. Seeking and playback show the selected source image, including guides. Solo and onion-skin views omit these image overlays. The model keeps its normal editing coordinates.
- Sequence import requires an absolute local directory and an explicit prefix (empty for purely numeric filenames). It refuses symbolic links, more than 4096 matching files, more than 100000 directory entries, or more than one billion decoded pixels. Reload and undo change links, not external file contents. `sourceFrame` in image readback is the numeric filename suffix; missing suffixes have `gap: true` and `path: null`. INP export drops sequence tracks and frame-step metadata.
- Exports omit unavailable images and continue. `imagesLeftOut` also reports unavailable linked sequence sources that the current remap may not select; hidden tracks and guides are excluded from this check.
- Verified: `animation_advance` before any `animation_seek` fails with "seek an animation before advancing it".
- Verified: keys of 0 at frame 0 and 1 at frame 30 sampled 0.5 at frame 15; keys of 1 at frame 10 and 2 at frame 20 sampled 1.5 at frame 15.
- Verified: a sample lists every parameter of the document, not only the animated one.
- Verified: `animation_create`, `animation_set` and `animation_key_set` answer with a full snapshot, so `revision` is in the reply.
- `random_pose_seek` is a pure function of seed and time (Soul2D's own formulas), is INX only, and never touches the manual values; `animation_key_add` still records the previewed value while it is shown, so reset first.
- `axis` is 0 for X and 1 for Y of a 2D parameter.
- A lane may run a repeating parameter (`parameter_set_repeat`) past its range to count turns: on a 0..4 parameter, keys of 0 and 12 turn it three times, and a negative value turns it the other way. `animation_sample` and `snapshot.values` keep the lane value (6 at the midpoint); the pose is the one `value_set 2` gives. Write such a key with `animation_key_set`: `animation_key_add` records the session value, which is already wrapped into the range. Without the flag a lane value past the range holds the pose at that end.
