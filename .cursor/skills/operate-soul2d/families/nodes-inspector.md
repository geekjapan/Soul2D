# Nodes and inspector

Status: run live against the headless host (create, rename, transform, property set, copy/paste, move, delete, undo, render, and every D-named row below in the shape it shows). Not run: the `Node_ConvertTo_*` names other than `GridDeformer` and `Composite`, and the `Inspector_Apply_*` names other than `CompositeOpacity`, `LockToRoot`, `TranslationX` and `ZSort`; they share a dispatcher branch with the ones run (inferred).

Create, find, reparent, rename and configure nodes of an INP/INX document. Parts get their texture from an import
(`merge_images`, `import_folder`, PSD); `node_create` cannot make a Part.

## Sequence

1. Explore: `nodes_list {}` (uuid, name, type, parent), or read `resource://soul2d/resources/find?selector=*`.
2. Read: `resource://soul2d/resources/<uuid>` for the full node (transform, mesh, tint, opacity, blend_mode, mask list).
3. Act: one call from the table. Every node argument is a UUID taken from step 1 or from `created` of a previous call;
   UUIDs are not reused predictably, so re-list after create, paste and import.
4. Confirm: `resource://soul2d/resources/<uuid>` shows the change; `render` (see render-scene.md) shows it visually.
   `undo` reverts one call.

## Tools

| Tool | Purpose and minimum arguments |
| --- | --- |
| `nodes_list` | List all nodes. No arguments. |
| `node_get` | `{id}` the full node record, the same content as `resource://soul2d/resources/<uuid>`. |
| `node_create` | `{className, name?, parents?:[uuid]}`. The default parent is the root. Classes seen to work: `Node`, `MeshGroup`, `Camera`, `GridDeformer`, `SimplePhysics`. A DepthRigRoot comes from `DepthBoneCommand_CreateDepthRigRoot`. `Part` is refused ("unsupported node class"). |
| `NodeCommand_AddNode` | `{className, _suffix, context?:{nodes:[parent]}}`: the new node's name is the parent's name plus `_suffix` (`Rootx`); with `_suffix: ""` it is `Unnamed Node`. Without `context` the parent is the root. A call without `className` or `_suffix` fails with "missing required argument(s) for NodeCommand_AddNode: ...". |
| `Node_Add_Camera` / `Node_Add_Composite` / `Node_Add_DepthBone` / `Node_Add_DepthRigRoot` / `Node_Add_DynamicComposite` / `Node_Add_GridDeformer` / `Node_Add_Mask` / `Node_Add_MeshGroup` / `Node_Add_Node` / `Node_Add_PathDeformer` / `Node_Add_SimplePhysics` | `{_suffix, context?:{nodes:[parent, ...]}}`: one new node per listed parent, named parent name plus `_suffix` (`Unnamed <Class>` with `_suffix: ""`), class fixed by the name (the classes `node_create` accepts; `Node_Add_DepthBone` needs a DepthRigRoot or DepthBone parent); `parents:[uuid]` also works, and wins when `context` is given too; a bare `nodes` is ignored (the node lands under the root). A sibling already holding the name fails with "Name already taken". A `className` argument is refused (see Gotchas). |
| `node_insert` | `{className, nodes}`: new node above each listed node, which is reparented under it. |
| `Node_Insert_Camera` / `Node_Insert_Composite` / `Node_Insert_DynamicComposite` / `Node_Insert_GridDeformer` / `Node_Insert_MeshGroup` / `Node_Insert_Node` / `Node_Insert_PathDeformer` | `{_suffix, context:{nodes}}`: the same insert with the class fixed by the name, named node name plus `_suffix` (`Ag` above `A`), or `Unnamed GridDeformer` with `_suffix: ""`. A bare `nodes` without `context` fails with "missing required argument(s) for <tool>: context". A `className`, `nodes`, `id` or `ids` argument beside them is refused (see Gotchas). |
| `node_convert` | `{className, nodes}`. Structural nodes only. `toType` is read when `className` is absent; with neither the call fails with "className is required". |
| `NodeCommand_ConvertTo` | `{className, context:{nodes}}`, one or several nodes (`toType` is accepted for `className`). A bare `nodes` fails with "missing required argument(s) for <tool>: context", a missing class with "className is required". |
| `Node_ConvertTo_Camera` / `Node_ConvertTo_Composite` / `Node_ConvertTo_DynamicComposite` / `Node_ConvertTo_GridDeformer` / `Node_ConvertTo_Mask` / `Node_ConvertTo_MeshGroup` / `Node_ConvertTo_Node` / `Node_ConvertTo_Part` / `Node_ConvertTo_PathDeformer` | `{context:{nodes}}`: `NodeCommand_ConvertTo` with the class fixed by the name. A `className` argument is refused (see Gotchas). |
| `node_rename` | `{id, name}`. Returns the whole node. |
| `NodeCommand_SetNodeName` | `{id, name}` as above, or the D form `{context:{nodes:[uuid]}, newNames:["name"]}` with exactly one node and one name (`context` with `name` fails "newNames must contain one name"). |
| `object_find` | `{text, types?:[typeId], caseSensitive?}` read only: answers `{matches:[{kind, typeId, uuid, name}]}` for every node, parameter and parameter group whose name contains `text` (case sensitive unless `caseSensitive:false`, which compares lowercase forms: a letter whose lowercase depends on its place, such as the Greek final sigma, does not match its capital), nodes first in document order, then parameters and groups in list order. `types` narrows by `typeId`: a node's `type` (`Part`, `Node`, ...), `Parameter` for parameters and groups. `text` is 1 to 256 characters. |
| `object_replace_name` | `{ids:[uuid], find, replace}` replaces every occurrence of `find` (exact case, 1 to 256 characters) by `replace` (may be empty) in the names of the listed nodes, parameters and parameter groups, in one undo step. Answers `{renamed:[{kind, uuid, from, to}], unchanged:[uuid]}` in the order of `ids`; an object whose name lacks `find` is `unchanged`, not an error, and a call that renames nothing adds no undo step. An unknown or repeated id, an empty resulting name, a resulting name longer than 4096 characters, the root, or a name taken by another node (or by another parameter or group) refuses the whole call and changes nothing. `ids` holds at most 4096 entries. |
| `object_export_csv` | `{path, overwrite?}` writes `uuid,type,name` for every node, parameter and parameter group to a `.csv` file (UTF-8, comma separated, one header row) in the order of `object_find`, and answers `{path, rows, bytes}`. Changes nothing. A type or a name that starts with `=`, `+`, `-`, `@`, a tab, a carriage return or an apostrophe is written after an apostrophe. Read `resource://soul2d/object/names-csv` for the same text as `{csv, rows}` without a file. |
| `object_import_csv` | `{path}` or `{csv}`, with `dryRun?`: renames the objects the rows name by `uuid`, in one undo step. Answers `{renamed:[{kind, uuid, from, to}], unchanged:[uuid], applied}`. An object without a row keeps its name, and one leading apostrophe of a type or a name is taken off. Refused whole: a `uuid` that names nothing or has two rows, a `type` that is not the type of the object, a name that would be empty, taken or longer than 4096 characters, more than 4096 rows or 1 MiB, text that is not UTF-8. Only names are read. |
| `node_transform` | `{id, translation?:[x,y,z], rotation?, scale?:[x,y], zsort?}` or `{id, component, value}`. `translation` needs three numbers here; `binding_set_trs` takes two. |
| `Inspector_Apply_TranslationX` / `Inspector_Apply_TranslationY` / `Inspector_Apply_TranslationZ` / `Inspector_Apply_RotationX` / `Inspector_Apply_RotationY` / `Inspector_Apply_RotationZ` / `Inspector_Apply_ScaleX` / `Inspector_Apply_ScaleY` / `Inspector_Apply_ZSort` | Aliases of `node_transform {id, component, value}` for one component. `{value, context:{nodes:[uuid]}}` with exactly one node and a number; the other components keep their values. |
| `node_property_set` | `{id, property, value}`: `lockToRoot`, `pinToMesh`, `zsort`, `tint`, `screenTint`, `opacity`, `mask_threshold`, `blend_mode`, `emissionStrength`, and class-specific ones listed in the manifest description. An unknown property returns "has no editable property". `blend_mode` takes the INX names of its node type (19 for a Part or a DynamicComposite, 17 for a Composite) and `LinearBurn`, `LinearLight`, `Hue`, `Color`. Those four are not modes of INX: `render` draws them with their formula, `render_packet` refuses them, and a program that knows the INX names only does not know them. `alphaBlend` takes `Over`, `Atop`, `Out`, `Conjoint` or `Disjoint` (absent means `Over`). Any but `Over` draws the Cubism formula of the `blend_mode` of the same name (`LinearDodge` as Add, `AddGlow` as Add (Glow)) with that composition; `render_packet` refuses it, and `Difference`, `Exclusion`, `Subtract`, `Inverse`, `DestinationIn`, `ClipToLower` and `SliceFromLower` take `Over` only. It is not a key of INX either. |
| `Inspector_Apply_CompositeBlendingMode` / `Inspector_Apply_CompositeOpacity` / `Inspector_Apply_CompositeScreenTint` / `Inspector_Apply_CompositeThreshold` / `Inspector_Apply_CompositeTint` / `Inspector_Apply_LockToRoot` / `Inspector_Apply_PartAutoResizedMesh` / `Inspector_Apply_PartBlendingMode` / `Inspector_Apply_PartEmissionStrength` / `Inspector_Apply_PartMaskAlphaThreshold` / `Inspector_Apply_PartOpacity` / `Inspector_Apply_PartScreenTint` / `Inspector_Apply_PartTint` / `Inspector_Apply_PinToMesh` / `Inspector_Apply_ViewportOrigin` | Aliases of `node_property_set` for one property. `{value, context:{nodes:[uuid]}}` with exactly one node (two fail with "Inspector apply requires exactly one context.nodes UUID"); an `id` or `nodes` argument is not read and the call fails with "missing required argument(s) for <tool>: context". A `property` or `id` argument beside them is refused (see Gotchas). |
| `node_enabled_set` / `node_enabled_toggle` | `{id, enabled}` / `{id}`. |
| `node_visibility_set` | `{nodes, enabled?, recursive?, siblings?}` hides or shows many nodes in one undo; omit `enabled` to toggle from the first. `siblings: true` makes each listed node stand for every child of its parent, so one top-level node with `siblings` and `recursive` covers the whole model below the root. The root itself has no siblings and is refused there. |
| `node_lock_set` | `{nodes, locked?, recursive?, siblings?}` locks or unlocks many nodes in one undo, with the rules of `node_visibility_set` and `locked` in the place of `enabled`. The node stores `locked` and the INX file keeps it. A lock stops one thing: a click in the editor viewport does not pick a locked node or any node below one. Every tool still edits a locked node. Read the result in the model (`locked` on the node) or in `scene_geometry` (`locked: true` on each Part under a lock). Tested (rust/tests/session_ops2.rs). |
| `NodeCommand_ToggleVisibility` | `{context:{nodes}}` toggles the first context node only; the other nodes are left as they are. Use `node_visibility_set` for several nodes. |
| `node_mask_edit` | `{id, action: add\|remove\|mode\|move, source, mode?, index?}` on the mask list of a Part, Composite or DynamicComposite; `mode` needs `mode: Mask\|DodgeMask`, `move` needs `index`. |
| `node_copy` / `node_cut` / `node_paste` | Session clipboard: `{nodes}` / `{nodes}` / `{parent, index?}`. A paste clones the subtree with new UUIDs and a trailing `'` in the names, and consumes the clipboard (an empty one fails "Clipboard empty"). `node_cut` also deletes the sources and answers `deleted`. The snake_case tools do not read `context` (`node_paste {context:{nodes}}` fails "paste parent is required"). |
| `NodeCommand_CopyNode` / `NodeCommand_CutNode` | `{context:{nodes}}`; a bare `nodes` fails with "missing required argument(s) for <tool>: context". Same clipboard as above. |
| `NodeCommand_PasteNode` | `{context:{nodes}, index?}` pastes under the first context node, or `{parent, index?}` / `{newParent, index?}`. With neither it fails with "context.nodes is required". |
| `node_move` | `{nodes, parent, index?}` reparent; answers `{moved, parent, index}`. `newParent` is read when `parent` is absent; with neither the call fails with "parent must be a positive resource UUID". |
| `NodeCommand_MoveNode` | `{newParent, index?, context:{nodes}}` reparent. `parent` is accepted for `newParent` and is the one read when both are given. |
| `node_delete` | `{nodes}` deletes the subtrees; answers `{deleted}`. |
| `NodeCommand_DeleteNode` | `{context:{nodes}}` deletes the subtrees. |

## Gotchas

- Verified: a failed call changes nothing and does not move `revision`.
- Verified: a name that is not in `tools/list` is refused with "unknown tool: <name>", also when it starts with `Node_Add_`, `Node_Insert_` or `Node_ConvertTo_` (`Node_Insert_Mask`).
- Verified: where a row shows a required `context:{nodes}` (`NodeCommand_ConvertTo`, `_CopyNode`, `_CutNode`, `_MoveNode`, `_DeleteNode`, `Node_Insert_*`, `Node_ConvertTo_MeshGroup`, `Inspector_Apply_CompositeOpacity`), a bare `nodes` or `id` instead fails with "missing required argument(s) for <tool>: context". Run for `NodeCommand_ConvertTo`, `_CopyNode`, `_CutNode`, `_MoveNode`, `_DeleteNode`, `Node_Insert_GridDeformer`, `Node_ConvertTo_MeshGroup`, `Inspector_Apply_LockToRoot` and `Inspector_Apply_TranslationX`.
- Verified: an argument that would replace a value the alias sets is refused and nothing changes. `Node_Insert_GridDeformer {_suffix, className:"MeshGroup", context:{nodes:[3]}}` fails with
  "Node_Insert_GridDeformer sets className itself: do not pass the argument className"; so do `Node_Insert_PathDeformer {_suffix, context:{nodes:[2]}, nodes:[3]}` (`nodes`),
  `Node_ConvertTo_MeshGroup {className:"Camera", context:{nodes:[2]}}` (`className`), `Inspector_Apply_LockToRoot {value:true, property:"pinToMesh", context:{nodes:[3]}}` (`property`) and
  `Inspector_Apply_TranslationX {value:5, component:"translationY", context:{nodes:[3]}}` (`component`). Where the alias hands `nodes` to the operation (`Node_Insert_*`, `Node_ConvertTo_*`, `NodeCommand_ConvertTo`, `_CopyNode`, `_CutNode`,
  `_MoveNode`, `_DeleteNode`), `id` or `ids` beside `context:{nodes}` is refused the same way ("... sets nodes itself: do not pass the argument id"). The `Inspector_Apply_*` aliases of this map hand over `id` instead: `id` beside `context` is
  refused with "... sets id itself: do not pass the argument id", while `ids` or `nodes` beside it is forwarded and not read (the context node is still the one edited).
  Any other argument an alias does not read is still forwarded to the session operation. Pass only the arguments in the rows.
- Verified: the snake_case tools that take `nodes` (`node_copy`, `node_cut`, `node_insert`, `node_delete`, `node_convert`, `node_move`, `node_visibility_set`) read `id` (one UUID) first, then `ids`, then `nodes`, so the manifest requires none of them
  (run: `node_copy {id}`, `node_convert {toType, ids}`, `node_move {nodes, newParent}`). With no target at all the call fails with "node UUIDs are required" and changes nothing (`node_insert` and `node_convert` once the class is given: `node_insert {}` answers "missing required argument(s) for node_insert: className" and `node_convert {}` "className is required"); `node_paste {}` fails with "paste parent is required".
- Verified: a Part made by `merge_images` is named after the file (`disc.png`); `import_folder` drops the extension.
- Verified: setting a property to the value it already has adds no history entry and keeps `revision`.
- Tested (rust/tests/object_find.rs): to rename many objects, call `object_find {text}` for the UUIDs and pass the ones you want to `object_replace_name {ids, find, replace}`. The pair covers names only: an INX object has no ID string, only a name and a numeric UUID. The root appears in `object_find` but cannot be renamed.
- Tested (rust/tests/object_csv.rs): to rename in a spreadsheet, read `resource://soul2d/object/names-csv` or call `object_export_csv {path}`, edit the `name` column only, and pass the text to `object_import_csv` with `dryRun:true` first. Rows may be left out, and two rows may swap names. The format is Soul2D's own: it was not checked against a CSV that Cubism Editor writes, and Shift_JIS is not read.
- Deformers, physics and mesh data have their own maps: deformers.md, physics.md, mesh-deform.md.
