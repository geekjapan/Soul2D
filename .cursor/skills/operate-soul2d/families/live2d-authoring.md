# Live2D authoring (CMO3 source)

Status: run in part. `tools/verify-acp-agent.py --families live2d-authoring` (2026-10-21) ran `live2d_parameter_edit` with `expectedRevision`, `undo`, `live2d_physics3_read` and `live2d_physics3_edit` against the headless host on the committed synthetic CMO3 `rust/tests/fixtures/physics3-editor.cmo3`, as a scripted MCP client and by an agent over ACP, and read back the parameter maximum and the group name. The typed physics tools and resource were also exercised over an owned headless MCP host; see Gotchas. Native GUI coverage includes only the named controls recorded below. Other rows retain their narrower evidence; vendor acceptance remains unverified.

Read and edit the source structure of a native Live2D CMO3 (and read CAN3 containers): meshes, keyform grids, morph targets, blend weights. These tools do not render or evaluate a Cubism
pose; see the manifest descriptions for every "does not" limit. Open the file with `open {path}` (session.md), or pass `path` to the read tools to query a file without opening it.

## Sequence

1. Explore: `live2d_authoring_inspect {path?}` container and model definitions; `live2d_authoring_read {path?}` source geometry, primary and generated forms, grids, morph targets, textures.
2. Read: `live2d_authoring_primary_forms`, `live2d_authoring_linear_weights`, `live2d_authoring_morph_forms`, each with `{path?, parameterValues?, sourceGuid?}`. Parameters not named in `parameterValues`
   use the active runtime values (set with `live2d_parameter_set`, live2d-expression.md) or the model defaults for a `path` query.
3. Act: `live2d_form_set_vertex` or `live2d_form_set_opacity`. Both need the exact `sourceGuid`, `formGuid`, `coordinateType` from step 1 and `expectedRevision` equal to the current `revision` (read
   `resource://soul2d/document/state` right before). A stale revision fails with "Live2D vertex edit revision conflict" / "Live2D opacity edit revision conflict".
   `live2d_rename {guid, name, expectedRevision}` renames one source or parameter under the same rule ("Live2D rename revision conflict"), and
   `live2d_user_data_set {guid, value, expectedRevision}` sets the user data of one ArtMesh ("Live2D user data revision conflict").
4. Confirm: read the same form back with `live2d_authoring_primary_forms`; `history_summary` shows the entry; `undo` reverts. `save` writes the CMO3 (session.md); `render` approximates the scene and lists warnings.

| `live2d_authoring_inspect` / `Live2DCommand_AuthoringInspect` | `{path?}` read only. |
| `live2d_authoring_read` / `Live2DCommand_AuthoringRead` | `{path?}` read only. A source with `data.type: "ArtPath"` carries `closed`, `divisionCount`, `lineAlgorithm`, `lineAlignment`, `brushGuid`, `clipGuids`, `invertClippingMask` and, per keyform, `data.points[]` with `guid`, `position`, `startVelocity`, `endVelocity`, `width`, `opacity`, `color` and `corner`. An ArtPath gets no `weights` and no `evaluatedForms` from the weight and form queries and is not drawn (a render reports "native ArtPath is read but not drawn" when a visible one exists). `live2d_rename` changes its name and `live2d_source_set` its clipping masks; its control points are edited with `live2d_artpath_point_set`, `live2d_artpath_point_add` and `live2d_artpath_point_delete`. |

One undo step; rendering/vendor acceptance separate. |
| `live2d_form_paste` | `{sourceGuid, formGuid, coordinateType, fromFormGuid, ratio?, invert?, properties?, expectedRevision}`: Paste/Blend Form within one ArtMesh or Warp source; positions (and ArtMesh opacity) become target + ratio × (copied − target); `invert` `vertical`/`horizontal` mirrors the copied shape about its bounds centre. One undo step. |
| `live2d_form_set` | `{sourceGuid, formGuid, coordinateType?, drawOrder?, multiplyColor?, screenColor?, angle?, origin?, scale?, reflectX?, reflectY?, intensity?, expectedRevision}`: stored settings of one form; draw order on ArtMesh and existing private ArtPath primary forms, colours on ArtMesh and Part, rotation settings on rotation deformer forms, intensity on Glue forms. ArtPath order is an integer `0..1000` and requires one existing plain `i/drawOrder` through private inline inheritance; missing, aliased/shared, shadowed, nested, CDATA, comment or escaped storage is refused, with no donor insertion. Legitimate identity references and surrounding XML whitespace including CR/CRLF are preserved. The original form's existing extended/morph guard is enforced by the writer. Live2D source forms exposes ArtPath Draw order through Apply form settings; ArtPath colour, opacity and rendering controls are separate. Other missing fields are copied from the same field elsewhere in the file ("the CMO3 stores no screenColor anywhere to copy its layout from" when there is none). One undo step; equal values are no-ops. |
| `live2d_brush_replace_image` | `{guid, path, expectedRevision}`: replace the existing shared image entry selected by one brush with a same-size static PNG. All brushes and meshes referencing that entry change; `affectedBrushes` and `affectedTextures` report the projected consumers. Checks complete chunk framing/CRC and bounded pixel decoding. No resizing, input selection or new entries. Identical bytes are a no-op; otherwise one undo step, with save and reopen support. |
| `live2d_brush_set` | `{guid, drawingCurveType?, widthCoefficient?, textureUvData?, fixWidthData?, spriteData?, textureInput?, expectedRevision}`: edit stored settings of one brush from `brushes[]` of `live2d_authoring_read`. `drawingCurveType` is `SPRITE` or `TIP_USE`; `textureUvData` takes `up`, `upInter`, `center`, `downInter`, `down`, `inStart`, `repeatStart`, `repeatEnd`, `outEnd`; `fixWidthData` takes `upFixedWidth`, `downFixedWidth`; `spriteData` takes `density`, `useTextureMagnification`. `textureInput.currentTextureInputData.optionalTransformOnCanvas` takes `m00`, `m01`, `m02`, `m10`, `m11`, `m12`. Use `live2d_brush_replace_image` for image bytes; input selection is unsupported. |
| `live2d_source_set` | `{guid, colorComposition?, alphaComposition?, invertClippingMask?, useOffscreen?, clipGuids?, closed?, divisionCount?, brushGuid?, expectedRevision}`: blend mode, clipping inversion, clipping mask ArtMeshes (`clipGuids`; also on ArtPaths), (Part) offscreen drawing and an ArtPath's stored `closed` boolean. Closure requires one existing direct private plain boolean; missing, duplicate, inherited, shared, nested, CDATA or escaped storage is refused. `divisionCount` edits an ArtPath's existing direct private plain `divNum` integer (0..4294967295), preserving surrounding whitespace; the same storage restrictions apply. `brushGuid` selects one existing listed brush through a direct private GUID slot, preserving shared definitions; a reference becomes an inline UUID when the destination has no ID. Encoded attribute whitespace is preserved. Combined settings use one undo step. These change stored settings; ArtPaths are not rendered and vendor acceptance is separate. Other missing scalar fields are copied from the same field elsewhere in the file; a missing mask list is copied, emptied, from another source of the same kind ("the CMO3 stores no clipGuidList anywhere to copy its layout from" when none stores one). One undo step; an unchanged value is a no-op. |
| `live2d_artpath_point_set` | `{sourceGuid, formGuid, coordinateType, index, position?, startVelocity?, endVelocity?, width?, opacity?, color?, corner?, expectedRevision}`: stored values of one ArtPath control point (stroke editing). ArtPaths are not drawn. One undo step. |
| `live2d_artpath_point_add` | `{sourceGuid, index, position?, startVelocity?, endVelocity?, width?, opacity?, color?, corner?, expectedRevision}`: insert a control point at `index` (0 to the number of points) into every keyform of one ArtPath. An ArtPath whose forms hold different numbers of points is refused. One undo step. |
| `live2d_artpath_point_delete` | `{sourceGuid, index, expectedRevision}`: delete control point `index` from every keyform of one ArtPath. The last point stays; a point the file names from elsewhere is refused. One undo step. |
| `live2d_reparent` | `{guid, parent, expectedRevision}`: move one source under another Part, at the end of its children; deformer and vertices unchanged. One undo step. |
| `live2d_reparent_deformer` | `{sourceGuid, targetDeformerGuid, expectedRevision}`: reattach one static ArtMesh to an existing static Rotation chain, changing only its target and sole DeformerLocal form positions. GUI: **Live2D objects → Rotation destination → Reparent to Rotation**; **Current target** stays separate from the draft and **Parent Part / Move**. Destination GUIDs appear in tooltips. Canvas coordinates are preserved within `1e-6` per coordinate; Part membership, mesh opacity, topology, UVs and material stay unchanged. Vendor parity is unverified. |
| `live2d_parameter_edit` | `{guid, minimum?, maximum?, default?, repeat?, expectedRevision}`: change the stored range, default and repeat flag of one parameter. The default must lie in the range, and so must every key a source has on it; a field the file does not store is copied from another parameter. One undo step. |
| `live2d_keyform_add` | `{sourceGuid, parameterGuid, key, expectedRevision}`: add a key inside the parameter's range to the axis of one ArtMesh or warp deformer. Each new form takes the vertices and opacity interpolated between its neighbours (or the end form's) and is written as a copy of a stored form. Blend shapes and extended interpolation forms are refused. One undo step. |
| `live2d_keyform_delete` | `{sourceGuid, parameterGuid, key, expectedRevision}`: delete one key and the forms on it from the axis of one ArtMesh or warp deformer; the last key stays. One undo step. |
| `live2d_duplicate` | `{guid, id?, expectedRevision}`: copy one ArtMesh, ArtPath, deformer, Glue or empty Part under the same parent, after the last source of its kind, or one parameter no source keys and physics does not use (at the end, in its group); or an ArtPath brush at the end of the brush list; the reply `guid` names the copy. A brush inherits the current settings, uses new texture-setting identities and shares image bytes and model-image references. A texture setting embedded in another model object is refused. The copy keeps the name and takes `id` (default `<id>_copy`). Written from the original's own XML with new GUIDs; a source the file names from outside the sources is refused when the model is written. One undo step. |
| `live2d_set_id` | `{guid, id, expectedRevision}`: change the ID string of one source, parameter or ArtPath brush (`brushes[].id`). `id` is 1 to 63 ASCII letters, digits or underscores, unused in its list. | `live2d_delete` | `{guid, expectedRevision}`: delete one source nothing else names (not the root Part, not a Part with children); its unused texture, the objects only it uses and a Cubism 2.1 conversion record naming it go too. A refusal says what names it. It composes with unsaved reparents, copies and deletions in the same session (for example, move or delete a Part's children, then delete the Part). | `live2d_parameter_delete` | `{guid, expectedRevision}`: delete one parameter no source keys and the physics does not use, with its group places. Motions keep their curves. One undo step. |
| `live2d_form_set_opacities` | `{forms:[{sourceGuid, formGuid, coordinateType}], opacity, method?: overwrite\|add, expectedRevision}`: ArtMesh and existing private primary ArtPath opacity; overwrite uses the single-setter finite native-float policy, while `add` accepts a finite delta and clamps each sum to 0..1. | `live2d_rename` / `Live2DCommand_Rename` | `{guid, name, expectedRevision}` sets the display name of one ArtMesh, ArtPath, Part, deformer or Glue (`sources[].name`) of one parameter (`parameters[].name`) or of one ArtPath brush (`brushes[].name`); `guid` comes from `live2d_authoring_read`, where the new name then shows (`resource://soul2d/document/state` gives the revision, not the model). An INX document is refused with "live2d.userdata3.export needs an active CMO3 document", a CAN3 document with "operation is not supported for the active CAN3 animation document". |
| `live2d_physics3_export` | `{path?}` answers the physics settings of the active CMO3 in the `.physics3.json` layout: `Version` 3, `Meta` (counts, `EffectiveForces`, `PhysicsDictionary` `{Id, Name}`, and `Fps` only when the CMO3 sets a rate) and `PhysicsSettings` with `Input`, `Output`, `Vertices` and `Normalization`. | `live2d_convert_inx` | `{path?, animation?, resourceGuid?}` converts the active CMO3 to an INX model (issue #146, the lossy mode approved on 2026-10-20): the default pose becomes the node tree with the CMO3 textures, and every parameter becomes a one-axis INX parameter whose axis points are 0, 1, the default and the keys of every source, each holding the `deform` offsets the pose at that key gives each ArtMesh. Single-parameter keys look the same as in the CMO3 (measured exact on the four samples); combined poses add in INX and differ (worst 38 to 3,062 px on the samples' pseudo-random combined poses). The answer is the loss report: `nodes`, `parameters`, `deformBindings`, `opacityBindings`, `zSortBindings`, `baked` (`warpDeformers`, `rotationDeformers`, `glues`, `sourcesWithBlendShapes`, `sourcesOnSeveralParameters`), `notConverted` (`opacityKeyChanges`, `physics`, `blendShapeConstraints`, `can3Animations`), `blendModes` (node counts per INX mode, `Cubism53` for the Cubism 5.3 additive compositions) and `warnings`. Keyed ArtMesh and offscreen-Part draw order and opacity become `zSort` and `opacity` bindings of the same parameter (the evaluator adds zSort and multiplies opacity); a node whose opacity several parameters key multiplies their ratios, so such combined poses differ, and `opacityKeyChanges` counts keyed opacities left out because the node is keyed by several parameters and drawn at opacity 0 at the default pose. With `animation` (a CAN3 path; `resourceGuid` picks the model resource when the CAN3 has several) every scene that drives the model becomes an INX animation named after the scene, with `length` = `durationFrames`, `timestep` = 1/fps and one Linear lane per keyed parameter holding frame-exact keyframes sampled by the CAN3 player (Bezier handles are baked; flat stretches keep their end frames only); each Part with opacity curves that fades a drawn node becomes a 0..1 `<Part> opacity` parameter (default: the Part's own opacity at the default pose) whose `opacity` bindings reach the nodes under the Part, with one lane per scene; the answer gains `animations` with `scenes`, `lanes`, `keyframes`, `partOpacityParameters`, `partOpacityLanes`, `skippedScenes` and `notConverted.partOpacityLanes` (Parts left out). Losses: a Part lane replaces the Part's own opacity in Soul2D's CAN3 player, so a node whose Part opacity is also keyed by a parameter differs while the lane plays; combined Part lanes multiply; a node drawn at opacity 0 at the default pose is not faded by a Part lane; a Part is also left out (counted in `notConverted.partOpacityLanes`) when a node it fades already has an opacity binding and is drawn at opacity 0 at the default pose. Between keys the INX draw order interpolates linearly where the CMO3 rounds to whole draw orders, so ties between meshes can resolve differently mid-key. With `path` it also creates the INX atomically; an existing destination is refused. No revision, no undo step. |
| `live2d_runtime_inspect` | `{path}` read only. | `live2d_physics3_edit` | `{expectedRevision, ...}` one typed edit of the CMO3 physics settings, one undo step; `expectedRevision` must equal the current `revision` (stale fails with "Live2D physics edit revision conflict"). A `group` index addresses one group by document order — two groups with identical values stay distinct. `field`+`value` sets `name`, `normalization.position.min|default|max` or `.angle.*` (min <= default <= max is kept); `field: "fps"` with no `group` sets the rate (integer 1..240, `null` clears). `list`+`index`+`field`+`value` edits one item of `inputs`, `outputs` or `vertices` (`source`/`destination` by parameter ID, input `type` `X`|`Angle`, `weight` 0..100, `reflect`, output `scale` and `vertexIndex` 1..vertexCount-1, vertex `x`, `y`, `mobility` 0..1, `delay`, `acceleration`, `radius`). `group`+`remove` removes a group, `list`+`index`+`remove` an item (outputs pointing to later vertices shift indices; deleting a vertex an output names is refused), `list`+`insert`+`value` inserts an item (`value` is an object of the item fields; vertices need all six fields, inputs need `source`+`type`, outputs need `destination`+`vertexIndex`; a vertex `insert` at index 0 of a nonempty strand is refused, the strand root stays fixed). `group`+`duplicate: true` appends a copy with new GUIDs and the next `PhysicsSetting<n>` ID. To create the first group in an existing empty inline settings list, omit `group`, `list`, `index` and `field`, and give `insert:0` plus `value:{name,normalization:{position:{min,default,max},angle:{min,default,max}},inputs:[],outputs:[],vertices:[]}`. All fields are required; populated arrays use the existing item shapes. Missing, null or shared sets and nonempty lists refuse donor-free creation. Inserted items use the known inline layout, and parameter fields take the file's own form (a reference to its shared GUID object when it keeps one). Ordinary edits refuse aliased or shared storage. With only `expectedRevision` and `detach:true`, make the complete known physics settings independent in one undo step, retaining original shared definitions, parameter identities, unknown markup and numeric precision. Already independent settings are unchanged. Direct fields and one-hop references only; unsupported inheritance, alias chains, conflicting alias metadata, ambiguous opaque references, cycles, serial overflow and copies beyond 16 MiB or 500,000 XML nodes refuse atomically. A failed edit changes nothing. With `group`+`list` (`inputs` or `vertices`)+`preset` (a name kept by `live2d_physics3_preset_save`, nothing else may be given) the list of that group becomes the preset in one undo step: the items both have are set field by field, the preset's extra items are inserted at the end, the group's extra items are removed from the end, and an item that already matches is not rewritten. A step the single edits would refuse (a parameter the file lacks, shared storage, an output that names a removed vertex) refuses the whole call. A preset the group already holds is no undo step; a name that is not saved fails with "no saved physics model preset is named" ("physics input preset" for `inputs`). |

Source identity references remain supported, and source flags add no form-cache/morph restrictions. Combined settings use one Undo step; equal values are no-ops. Existing ArtPath rename and clipping-mask APIs are unchanged. Rendering and vendor acceptance are separate.
- Existing ArtPath metadata is available in **Live2D source forms**: Closed, Division count, a listed Brush, Invert clipping mask and Clipping masks use **Apply source settings**; primary-form Draw order uses **Apply form settings** with the selected coordinate identity. Unknown current brushes are retained; no brush is invented. Each request sends only changed supported settings, with the loaded revision; storage refusal retains the draft. This GUI route adds no ArtPath colour, point, creation or rendering controls. Native acceptance is separate from headless panel tests.
- ArtPath primary forms directly offer **Opacity / Apply opacity** through `live2d_form_set_opacity`, without vertex controls. Use the actual selected coordinate. Finite authored values are not clamped to `0..1`; native float range and existing private storage are still checked. Form opacity is separate from point opacity. Applying any one of opacity, form settings or source settings retains the other drafts and advances their revision guards. Refusal retains the input; external conflict requires Reload. Native GUI and rendering/vendor acceptance remain separate.
