# Commands

Status: Current for the Rust port. The manifest is generated from `rust/src/manifest.rs`. The result of a call is
described in [command_palette.md](command_palette.md).

`doc/commands.manifest.json` is the machine-readable list of the MCP tools that
`soul2d-core` and the editor expose. It is generated from the tool registry in
`rust/src/mcp.rs` and must not be edited by hand.

## Regenerate and check

```sh
./tools/verify-command-manifest.sh
```

The script runs `soul2d-core --export-command-manifest doc/commands.manifest.json`,
runs it again with `--check` (exit 1 if the file differs from a fresh export), and
validates the JSON. It then runs `tools/verify-operating-skill.py`, `tools/verify-editor-dispatch.py`,
`tools/gen-gui-entries.py --check` and `tools/gen-edit-ops.py --check`. To only check, without writing:

```sh
cargo run --offline --manifest-path rust/Cargo.toml --target-dir out/rust --bin soul2d-core -- \
  --export-command-manifest doc/commands.manifest.json --check
```

## Manifest shape

The file has two top-level keys:

- `generator`: the string `soul2d-core --export-command-manifest`.
- `commands`: an array sorted by `id`. Each entry has:

| Key | Meaning |
| --- | --- |
| `id` | Tool name, as listed by `njc tools list` (for example `NodeCommand_AddNode`). |
| `description` | The tool description. |
| `inputSchema` | The JSON Schema of the tool arguments, inline (no `$defs`). |
| `scope` | Currently always `["global"]`. |
| `mcpExposed` | Currently always `true`; every listed tool is registered with MCP. |
| `headless_ok` | `true` when the tool runs in `soul2d-core` without a window. `false` for the `editor_*` tools, which set editor state: only `soul2d-editor` runs them, and `soul2d-core` refuses them (see "Editor State" in [mcp_api.md](mcp_api.md)). |
| `effect` | Slug for what the tool does, set by `effect_of` and `effect_from_schema` in `rust/src/manifest.rs`; see below. |
| `guiEntry` | Optional. Array of the Soul2D GUI entries that reach the tool, from `rust/src/manifest_gui_entries.rs`. A tool that `doc/gui-operation-inventory.md` does not name has no `guiEntry` key. |

`effect` values, in the order the exporter decides them:

- `-`: the tool reads and changes nothing (the `READ_ONLY` list).
- `project-reset`, `file-write`, `import`, `clipboard-write`: tools named in the lists of the same name.
- `application-lifecycle`: `editor_quit`.
- `document-edit`: the schema takes `expectedRevision`, or the operation reaches a document-replacing sink
  (`rust/src/manifest_edit_ops.rs`, generated by `tools/gen-edit-ops.py`).
- `editor-state`: any other `editor_*` tool.
- `session-state`: the operation changes state the session holds without replacing the document (also from
  `manifest_edit_ops.rs`).

The exporter omits `effect` for a tool none of these rules reaches. The checked-in manifest has an `effect` on every
entry. The exporter code does not guarantee that, so do not rely on it.

## What the manifest no longer records

The earlier manifest was generated by the D application from per-command
metadata. These fields have no Rust source and are no longer produced:
`runnable()`, `shortcutRunnable()`, hidden Command Browser arguments, the node
template switch, `guiDisplay`, and the `rustCore` support lists. The long
D-era table of command classes and their source files was removed with them. It
described `.d` files that no longer exist, and nothing can regenerate it.

## Using the tools

- In the editor's Command Browser, Enter or a double-click runs a tool immediately
  only when its schema declares no arguments. For a tool with required or optional
  arguments, select it, edit the JSON, then click **Run Command**. The JSON template
  includes required fields only, so omitted optional fields keep their defaults.
- `./out/rust/debug/njc --port 18088 tools list` prints the live definitions,
  including `inputSchema`; `tools call NAME --json 'JSON'` runs one.
- `njc` exiting with zero does not prove a command succeeded. Check the JSON-RPC
  `error` and the MCP `isError` flag.
- See [mcp_api.md](mcp_api.md) for the MCP resources.
