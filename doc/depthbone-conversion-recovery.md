# DepthBone target conversion and refresh recovery

Status: implemented in `rust/src/bindings.rs`, `rust/src/nodes.rs` and `rust/src/dirty.rs`. Convert, delete and paste
rewrite the rig binding table in the same candidate model as the node change, and a failed refresh aborts the whole
edit. Not implemented: asynchronous GPU actions, a per-frame flush wrapper and error notifications, because the Rust
core has no frame loop and its CPU offsets are the stored result.

## Problem

A rig binding keeps the target UUID. If the target node turns into a node that the rig cannot deform, such as a plain
`Node`, the binding would still name it. A refresh that then builds offsets for a target that is not a binding target
would fail. The rig needs the table and the node type to change together.

## Behaviour

The table is rewritten before the refresh is planned, so the refresh never sees a target that is no longer valid
(`dirty::marks_for_structure` doc comment).

- Convert (`nodes::convert_nodes`, `Session::op_node_convert`) calls `bindings::retarget_converted_node`. A binding
  whose target becomes `GridDeformer` or `PathDeformer` keeps its sources, source settings and influence rule and gets
  the new `targetKind` (`grid` or `path`). Any other target type, including `Part` and `Node`, drops the row. A rig
  whose last row is dropped loses its `bindings` key.
- Delete and cut (`nodes::delete_nodes`) call `bindings::drop_deleted_references`. It drops rows whose target was
  removed. For a removed source bone it drops the bone from `sourceBoneUuids`, `sourceSettings` and
  `multipliersByBoneUuid`, and drops the row if no source is left. If the row has `vertexWeights`, the delete fails
  ("vertexWeights must be cleared before the source list changes").
- Copy and paste (`nodes::copy_nodes`, `nodes::paste_nodes`, and `app_shell::remap_subtree`) call
  `bindings::remap_copied_bindings`, which maps target and source UUIDs to the copied nodes.
- `dirty::marks_for_structure(before, after)` compares each rig's `bindings` and bone set before and after, and marks
  the rig root for an all-keypoint refresh when they differ. `plan.md` describes the refresh.
- A deform row that the rig wrote for a dropped target stays on the parameter. It is only regenerated by a later
  `rig_add_source` (test `leftover_deform_survives_convert_until_add_source`). A target whose deform row was not
  rig-driven keeps its offsets across convert (`converting_an_undriven_deform_row_keeps_the_offsets`).
- The edit, the table rewrite and the refreshed keys are one history step. One undo restores the original node type, the
  original binding including source settings and influence multipliers, and the sibling targets' deform keys.

## Failure

`Session::commit_marked_keeping` runs `dirty::flush` on the candidate and returns its error before anything is
committed. A failed refresh (for example a target larger than `bone_deform::MAX_VERTICES`) leaves the document, history
and revision as they were, and the same request fails the same way on retry. There is no "discard pending work and
continue next frame" path. A failure returns to the caller of the operation, so a command cannot report success after
a failed refresh. Notification is up to the caller: not verified in the Rust port for the egui editor.

## Regression coverage

In `rust/src/dirty.rs`:

- `convert_drops_the_node_binding_and_refreshes_the_sibling_in_one_undo`: convert to a plain node, the other target's
  deform key refreshes, one undo restores the grid with its source settings and multipliers.
- `delete_drops_one_bone_source_and_refreshes_deform_in_one_undo`: deleting one source bone, its settings and multiplier
  go, the remaining bone drives the refresh, and undo/redo restore the complete binding state.
- `leftover_deform_survives_convert_until_add_source`, `converting_an_undriven_deform_row_keeps_the_offsets`.
- `failed_convert_refresh_is_not_retried`: adding a source on an over-limit target makes the refresh fail, the snapshot
  does not change and a retry fails the same way. (Despite the name, the failing request is `rig.add_source`.)

In `rust/tests/core.rs`: `binding_table_follows_delete_convert_and_paste`.
